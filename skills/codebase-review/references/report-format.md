**모드**: base-diff (`{base}...HEAD`) / full / `{git-rev}` / --working / --staged

**리뷰 상태**: `REVIEW_STATUS: {ran (M/N) | no-target (사유) | aborted (사유)}`

## 도메인 교차 발견 — Top 10에서만 합친다

도메인 렌즈는 겹친다. 같은 코드를 backend는 구조로, security는 노출로 본다. **여러 도메인이 같은
것을 잡았다는 사실은 노이즈가 아니라 신호다.**

**도메인별 상세 섹션은 각 리뷰어의 리포트를 그대로 둔다.** 합치는 것은 Top 10 집계뿐이다.

묶는 기준은 둘이고, **둘 다 인용을 근거로 한다**. backend·frontend·security는
`../reviewers/evidence-gate.md`가, conformance는 자기 기준 문서 인용 규칙이 인용을 강제한다.
**conformance 발견은 코드 앵커가 없을 수 있으므로 기준 1번(같은 지점)으로만 묶는다.**

1. **같은 지점** — `{파일}:{라인}:{유형}`이 같다. 라인이 없으면 `{파일}:{유형}`.
2. **같은 것을 다른 지점에서** — 인용한 **심볼·구성물이 겹치고** 두 서술이 같은 사실을 가리킨다.
   한쪽은 정의부를, 다른 쪽은 호출부를 앵커로 잡은 경우가 이것이다.

**인용이 겹치거나 지점이 같아야 같은 발견이다.**

묶은 뒤:

- **한 항목으로 낸다.** 심각도는 가장 높은 것을 쓰고, 도메인 열에 전부 적는다.
- **앵커는 전부 남긴다.** 2번으로 묶은 항목은 도메인별 `파일:라인`을 모두 적는다 — 어느 하나가
  진짜 지점인지 집계 단계에서 정하지 않는다.
- 설명이 다르면 버리지 말고 이어 붙인다 — 서로 다른 각도가 그 발견의 근거다.
- 두 도메인 이상이 잡은 항목은 **같은 심각도의 단독 발견보다 위에 둔다.**

## 대시보드 셀의 세 가지 상태

이 셀은 사람용이다. 이 스킬을 감싸는 쪽은 `REVIEW_STATUS` 줄로 판정한다.

| 상태      | 표기                   | 의미                                                              |
| --------- | ---------------------- | ----------------------------------------------------------------- |
| 이슈 없음 | `0`                    | 에이전트가 대상 파일을 리뷰했고 발견 사항 없음                    |
| 대상 없음 | `N/A (대상 파일 없음)` | `files`에 해당 도메인 파일이 없음. 에이전트를 안 띄웠든 띄우고 대상 없이 종료했든 같은 표기 |
| 미실행    | 테이블에서 제외        | 사용자가 `--domain`으로 도메인을 골라 제외했다                    |
| 무응답    | `무응답`               | 에이전트를 띄웠으나 리포트를 반환하지 않았다. 검사되지 않았다     |

**대시보드 발견 수는 도메인별 원시 수치다** — 교차 dedup 전 값이라 Top 10 항목 수와 합이 다를 수 있다.
**`미검증 관찰`은 발견 수에 세지 않는다**(`../reviewers/evidence-gate.md`). 도메인별 상세에는 그대로 남긴다.

`0`은 검사 결과이고 `N/A (대상 파일 없음)`과 `무응답`은 미검사다. 세 표기를 구분해서 쓴다.
어느 도메인이 `무응답`인지와 그때의 `REVIEW_STATUS` 값은 `SKILL.md` Phase 4가 판정한다.

## 리포트가 길 때

Top 10 + 도메인별 Top 5로 요약한다.

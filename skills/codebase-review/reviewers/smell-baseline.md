# 코드 스멜 베이스라인

`reviewers/backend.md`와 `reviewers/frontend.md`가 패스 B(중복·복잡도)에서 읽는다.
프로젝트가 코딩 표준을 문서화하지 않았을 때도 적용되는 고정 목록이다.

## 이 목록을 거는 두 가지 조건

**프로젝트 규칙이 이긴다.** 대상 프로젝트의 CLAUDE.md·AGENTS.md·CONTRIBUTING이 이 목록이
지적할 형태를 명시적으로 승인하면 보고하지 않는다.

**전부 판정이다.** 각 항목은 "여기서부터 의심하라"는 신호이지 위반이 아니다. 보고할 때
`가능성` 수준의 확신도를 붙이고, 근거는 형태가 아니라 **결과**로 든다 — 무엇을 이해하기
어렵게 만드는가, 어떤 변경을 위험하게 하는가(`backend.md`·`frontend.md`의 「판정 기준」 절).

린터·포매터가 이미 강제하는 항목은 보고하지 않는다.

**한 사실은 한 번만 보고한다.** 같은 코드가 패스 A의 구조 항목이나 B2 복잡도로 이미 보고됐으면
스멜 이름으로 다시 올리지 않는다.

## 목록

각 항목은 *무엇인가* → *어떻게 고치는가* 순으로 읽는다.

- **Mysterious Name** — 이름이 하는 일이나 담은 것을 드러내지 못하는 함수·변수·타입.
  → 이름을 바꾼다. 정직한 이름이 안 나오면 설계가 흐린 것이다.
- **Data Clumps** — 같은 필드·파라미터 몇 개가 계속 함께 다닌다(태어나고 싶은 타입).
  → 하나의 타입으로 묶어 그것을 넘긴다.
- **Repeated Switches** — 같은 타입에 대한 `switch`·`if` 연쇄가 변경분 여러 곳에 반복된다.
  → 다형성으로 대체하거나 두 지점이 공유하는 맵 하나로 만든다.
- **Shotgun Surgery** — 논리적으로 하나인 변경이 여러 파일에 흩어진 수정을 강요한다.
  → 함께 변하는 것을 한 모듈로 모은다.
- **Divergent Change** — 한 파일·모듈이 서로 무관한 여러 이유로 수정된다.
  → 각 모듈이 한 가지 이유로만 변하도록 쪼갠다.
- **Speculative Generality** — 요구에 없는 필요를 위해 넣은 추상·파라미터·훅.
  → 지운다. 실제 필요가 나타날 때까지 인라인으로 되돌린다.
- **Message Chains** — 호출자가 의존하면 안 되는 긴 `a.b().c().d()` 탐색.
  → 첫 객체의 메서드 하나 뒤로 그 탐색을 감춘다.
- **Middle Man** — 대부분 위임만 하는 클래스·함수.
  → 없애고 실제 대상을 직접 호출한다.
- **Refused Bequest** — 상속받은 것 대부분을 무시하거나 덮어쓰는 서브클래스·구현체.
  → 상속을 버리고 합성을 쓴다.
- **God function / God component** — 여러 관심사를 한 몸에서 처리한다.
  → 관심사별로 분리한다.
- **Feature Envy** — 자기 데이터보다 다른 객체의 데이터를 더 많이 만지는 메서드.
  → 탐내는 데이터 쪽으로 메서드를 옮긴다.
- **Primitive Obsession** — 자기 타입을 가질 자격이 있는 도메인 개념을 기본형·문자열이 대신한다.
  → 그 개념에 작은 타입을 준다.
- **Boolean 파라미터** — 함수 동작을 분기시키는 bool 인자.
  → 함수를 분리한다.

**Duplicated Code는 이 목록에 없다.** 중복은 전역 검색이 필요해 `shared-lenses.md`가
범위와 보고 위치를 따로 정의한다.

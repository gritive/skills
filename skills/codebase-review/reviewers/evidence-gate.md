# 근거 인용 게이트

`reviewers/backend.md`·`frontend.md`·`security.md`가 발견을 리포트에 올리기 전에 통과시키는 게이트다.
이 게이트는 **모든 발견**에 걸린다.
`conformance.md`는 기준 문서 인용이라는 자기 규칙을 쓴다.

## 규칙

**발견마다 그것을 유발한 코드를 `파일:라인`과 함께 그대로 인용한다.** 요약이나 재서술이 아니라
그 줄의 원문이다.

| 발견의 형태                  | 인용해야 하는 것                             |
| ---------------------------- | -------------------------------------------- |
| "X가 Y에 없다"               | X가 있어야 할 Y의 정의부                     |
| "이 값이 비어 있을 수 있다"  | 그 값을 만드는 초기화·대입부                 |
| "A와 B 사이에 경쟁이 있다"   | A와 B 양쪽                                   |
| "이 입력이 검증되지 않는다"  | 입력이 들어오는 지점과 사용되는 지점         |
| "N+1이 발생한다"             | 반복문과 그 안에서 호출되는 쿼리             |

**인용할 줄을 못 찾으면 그 발견은 미검증이다.** 리포트 표에서 빼고 `### 미검증 관찰` 절에만 남긴다.
확신도를 높여 잡아 이 게이트를 우회하지 않는다.

## 프레임워크가 만드는 심볼

심볼이 코드에 문자 그대로 없는 것이 정상인 경우가 있다. ORM 메타클래스, 디스크립터,
데코레이터, 스키마 파일, 마이그레이션, 코드 생성기 산출물이 만드는 것들이다.

이때는 **그 심볼을 만드는 구성물을 인용한다** — 메타 선언 블록, 데코레이터, 스키마 정의,
마이그레이션 파일. 인용은 "이름으로 검색해서 안 나왔다"가 아니라
**"그 심볼을 만드는 소스를 읽었다"**를 뜻한다.

## 출력

미검증 관찰은 리포트 끝에 이 형식으로 붙인다. 없으면 절 자체를 뺀다.

```markdown
### 미검증 관찰

| 파일:라인 | 관찰 | 인용 실패 사유 |
| --------- | ---- | -------------- |
```

# 공통 렌즈 규약 — 데드코드·코드 중복·문서 staleness

`reviewers/backend.md`와 `reviewers/frontend.md`가 이 세 렌즈를 수행할 때 읽는다.
셋 다 판정에 **전역 검색**이 필요하다는 점에서 다른 렌즈와 다르다. 검색은 전역으로 하되
**보고 범위는 `files` 안**이다(아래 데드코드 예외 하나만 제외).

## 코드 중복 렌즈

`base-diff` 모드에서 보고하는 것은 둘이다.

- 대상 파일 **내부**의 중복
- 대상 파일이 **기존 코드와 중복**되는 경우 → 보고 위치는 **대상 파일**이다.
  기존 코드 쪽을 이슈로 올리지 않고 "이미 {기존 파일}에 동일한 것이 있다 — 재사용하라"로 기술한다.

비교 상대 검색은 **이 변경이 추가한 블록만** 대상으로 건다. 기존 블록끼리의 중복은 이 변경이
만든 것이 아니다.

## 데드코드 렌즈 — 보고 범위의 유일한 예외

`base-diff` 모드의 질문은 "이 코드베이스에 데드코드가 있는가"가 아니라
**"이 변경이 데드코드를 남겼는가"**이다.

- 대상 파일에서 **정의된** 심볼 → 전역 검색으로 참조 0건인지 확인한다.
- 이 변경이 **삭제한 참조**가 유일한 사용처였다면 피참조 심볼이 고아가 된다. 이 심볼은
  `files` 밖에 있어도 보고한다 — **이 변경이 직접 유발한 데드코드**다.

**근거 문구는 하나로 고정한다:** `"{대상 파일}이 마지막 참조를 제거함"`.
이 문구가 없는 `files` 밖 항목은 호출자가 제거한다(`../SKILL.md` Phase 4).

**예외의 한계는 1홉이다.** 심볼 A가 죽었다고 해서 A가 쓰던 B, C까지 연쇄로 보고하지 않는다.
"직접 유발"은 **대상 파일이 제거한 참조의 직접 피참조 심볼까지**를 뜻한다. 전이 폐포를 따라가면
잘 나뉜 코드베이스에서 모듈 절반이 보고 대상이 된다.

참조 검색은 **이 변경이 추가·삭제·이름변경한 심볼만** 대상으로 건다. 손대지 않은 기존 심볼은
이번 변경이 고아로 만들 수 없다. 순수 추가만 있는 변경에서도 **새로 추가한 export는 검사한다** —
아무도 부르지 않는 새 심볼은 진짜 발견이다.

**무엇이 삭제됐는지는 `base`로 직접 본다.** `files`는 파일 목록일 뿐 diff가 아니다.

```bash
git diff {base} -- {files}                      # 대상 파일에서 삭제된 라인
git diff --name-only --diff-filter=D {base}     # 통째로 삭제된 파일
```

**통째로 삭제된 파일은 `files`에 없다**(스킬이 `--diff-filter=d`로 제외한다). 파일 삭제는 심볼을
고아로 만드는 가장 흔한 경로이므로 위 명령으로 따로 확인한다.

## 문서 staleness 렌즈

데드코드가 "이 변경이 죽은 코드를 남겼나"라면, 이 렌즈는 **"이 변경이 낡은 문서를 남겼나"**다.

**검색 대상은 고정이다.** 다음 셋을 대조하면 이 렌즈는 끝난 것이다.

1. 저장소 루트의 `CLAUDE.md`·`AGENTS.md`·`README`
2. 대상 파일이 속한 디렉터리와 그 상위의 `*.md`
3. 대상 파일이 export하는 심볼명·모듈 경로로 검색한 `*.md`

**보고 위치는 대상 파일이다**(중복 렌즈와 같다). 문서 파일을 별도 항목으로 올리지 않고
"이 변경이 `{문서 경로}`의 `{절}`을 낡게 함"으로 기술한다.

**심각도는 LOW 고정이다.** 문서 갱신은 이 변경의 요구가 아니다.

**보고는 어긋난 문장을 인용할 수 있을 때만 한다**(`evidence-gate.md`). 검색은 매번 같은 셋을
훑지만 보고되는 것은 이 변경이 실제로 거짓으로 만든 문장뿐이다 — 인용 요건이 반복 보고를 막는다.

## 정적 검색으로 놓치는 참조

참조 0건을 곧바로 "죽었다"로 판정하는 대신, 아래에 해당할 가능성이 있으면 **확신도를 낮추고
근거를 적는다.** 이름으로 직접 호출되지 않아 검색에 잡히지 않는 것들이다.

- 문자열로 조립되는 심볼명·클래스명·라우트, 리플렉션/동적 디스패치, DI 컨테이너 등록
- 프레임워크 규약 기반 진입점 (라우트 파일, 파일 기반 라우팅, 라이프사이클 훅, 슬롯,
  마이그레이션, CLI 서브커맨드)
- 코드 생성기의 산출물 또는 입력, 빌드 타임에만 참조되는 심볼
- 외부 소비자가 있는 공개 API (라이브러리·SDK·디자인 시스템이라면 미사용 export가 곧 데드코드가
  아니다)

도메인별로 더 잡히는 항목은 각 리뷰어 문서의 "도메인별 예시" 절에 있다.

# Plugin 테스트: 대상 프로젝트 파일 편집과 원복

Phase 3에서 `plugin` 인터페이스를 시뮬레이션할 때 이 문서를 읽고 따른다.

`plugin` 인터페이스는 hook을 띄우려면 대상 프로젝트 파일을 건드려야 한다. 테스트 조작이므로 허용하되
반드시 원복한다. 다음 순서로 한다:

1. 가능하면 **새 임시 파일**을 만들어 트리거하고 테스트 후 지운다. 기존 파일을 건드리지 않는 게
   가장 안전하다
2. 기존 파일을 고쳐야만 하면, 먼저 **`cp`로 산출물 디렉토리에 원본을 백업한다.** git 저장소면
   `git status`로 **그 파일에 커밋되지 않은 변경이 있는지 본다. 있으면 건드리지 않는다** — 원복이
   사용자 작업을 날린다
3. 테스트 후 **백업본을 `cp`로 되돌려** 원복한다. 2단계에서 그 파일이 clean임을 확인했으므로 파일
   하나를 지정한 `git checkout -- <파일>`도 안전하다
4. 도중에 중단되면 남아있는 편집을 사용자에게 알린다

**원본을 `Read`해서 기억했다가 `Write`로 되쓰는 방식으로 원복하지 않는다.** `Read`는 줄번호를
붙이고 긴 파일을 잘라서 보여주므로, 그 내용을 되쓰면 **사용자 파일이 잘린 채 덮어써진다.** 원복은
바이트 단위 복사(`cp`)나 `git checkout -- <파일>`로만 한다.

**전역 복원 명령을 쓰지 않는다.** `git checkout -- .`, `git restore .`, `git stash`는 이 스킬이
건드리지 않은 사용자의 작업까지 날린다. 원복 대상은 **내가 고친 파일뿐이다.** `git status`에
무관한 변경이 보여도 그건 사용자 것이니 손대지 않는다.

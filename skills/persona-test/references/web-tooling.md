# Web UI 브라우저 도구와 스크린샷

Phase 3에서 `web` 인터페이스를 시뮬레이션할 때 이 문서를 읽고 따른다.

**Web UI는 현재 세션에서 사용할 수 있는 브라우저 자동화 도구로 조작한다.** 시작 전에 탐색, 의미 기반
요소 조회·조작, 대기, 스크린샷, 격리된 임시 컨텍스트나 프로필을 지원하는지 확인한다. 이 핵심 기능 중
하나라도 없으면 `blocked`다. 새 탭만 여는 것은 쿠키·스토리지를 공유하므로 격리가 아니다. 격리된
컨텍스트에서 대상 URL로 바로 이동하고 **한 페이지에서 시나리오를 진행한다** — 탭은 하나만 쓴다.

다이얼로그가 있는 시나리오에서 처리 기능이 없으면 해당 시나리오는 실행하지 않고 `degraded`와
`coverage=partial`에 남긴다. 콘솔이나 네트워크 관측 기능이 없으면 사용자 여정은 계속하되 Bug의 기술적
증거를 수집하지 못한 사실을 `degraded`에 남긴다. 여러 도구를 함께 써서 기능을 충족해도 된다.

**조작은 스냅샷 기반으로 한다.** 도구가 제공하는 접근성 트리나 DOM 스냅샷에서 요소 참조를 얻어
클릭·선택한다. 좌표 클릭보다 요소 참조를 우선해 페르소나가 실제로 상호작용하는 요소를 정확히 겨냥한다.
동적 로딩·전환은 도구의 대기 기능으로 기다린다. **폼은 가능하면 한 번에 채운다.** 로그인은 거의 모든
시나리오의 첫 단계이므로 Phase 1-2에서 로딩한 **테스트 계정의 아이디·비밀번호로** 직접 로그인한다.

**다이얼로그를 띄우는 조작 전에 도구의 다이얼로그 처리 기능을 준비한다.** `confirm()`·`alert()`가 뜨면
이후 모든 브라우저 호출이 막혀 세션이 죽는다. 삭제·취소·이탈 확인은 흔하고, 페르소나 시나리오는
그것들을 실제로 누른다. 다이얼로그로 막혔으면 도구 문제이므로 처리한 뒤 시나리오를 이어간다.

**주요 화면은 스크린샷으로 남겨 보존한다 — 나중에 쓸 수 있게.** 스크린샷은 근거 보존용인 동시에
**시각적 UX 평가의 판정 근거**다 (SKILL.md Phase 4의 관찰 축 참조). 판정은 페르소나가 실제로 보는
렌더된 화면으로 한다. 빈 상태·에러 화면·완료 화면, 페르소나 시나리오의 각
핵심 단계 등 발견사항의 근거가 될 화면은 반드시 찍는다:

- 도구의 스크린샷 기능에 알아보기 쉬운 파일명을 주어 저장하고, 반환된 실제 저장 경로를 확인한다
- 실행 중에는 반환 경로를 산출물 디렉토리로 옮기고(`cp`/`mv`) 리포트에서 참조한다. 파일명은
  `{페르소나ID}-{단계}.png`처럼 **나중에 찾기 쉽게** 붙인다
- 리포트의 각 발견사항에 근거 스크린샷을 연결하고, 핵심 화면은 `SendUserFile`로 사용자에게 전달한다

## 콘솔·네트워크는 증거이지 판단 근거가 아니다

Bug로 기록할 것(빈 화면, 저장 안 됨, 멈춤)을 만나면 **그때** 도구가 제공하는 콘솔 오류와 네트워크 요청을
읽어 **API 경로만 골라** 발견에 붙인다. "빈 화면이 떴다"와 "빈 화면 —
`GET /api/tasks` 500"은 이슈로서 값이 다르다. 이 스킬의 발견은 **이슈로 등록되고 구현자에게 넘어가므로**,
근본 원인이 없으면 구현자가 재현부터 다시 해야 한다.

**단, 이것을 시뮬레이션 중 판단에 쓰지 않는다.** 페르소나는 콘솔을 못 본다 — 네트워크 로그를 읽고
"아 서버 문제군" 하며 마찰을 뚫고 지나가면 이 테스트는 무효다(SKILL.md Phase 3의 "페르소나 역량으로 행동하기").
순서가 규칙이다: **화면만 보고 막힌다 → 막힌 것을 기록한다 → 그제서야 증거를 붙인다.**
증거는 Bug에만 붙인다. Friction·Gap은 동작이 아니라 경험의 문제다.

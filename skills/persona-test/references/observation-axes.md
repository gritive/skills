# 관찰 축 상세 — AI slop 판정과 인터페이스별 추가 관찰

`SKILL.md` Phase 4에서 공통 관찰 축을 채울 때 읽는다. 공통 축 자체는 그 문서가 정한다.

## AI slop 판정

관찰 축의 하나이며, 아래 신호가 **페르소나 눈에 보이는 표면**(UI 문구·CLI 출력·API 메시지·응답 본문)에
있을 때 기록한다. 코드 스타일은 대상이 아니다 — 그건 `codebase-review`가 본다.

- **빈 문구**: 무엇을 하는지 말하지 않는 홍보성 문장("혁신적인", "손쉽게", "원활한 경험")
- **자리 표시자 잔존**: `Lorem ipsum`, `TODO`, `example.com`, 더미 이름·금액이 실서비스 화면에 노출
- **모델 말투 누출**: "As an AI", "죄송합니다, 저는", 답변 앞뒤의 사과·요약 상투구, 근거 없는 확신
- **장식 과잉**: 의미 없는 이모지·불릿 남발, 내용보다 많은 강조, 같은 말을 표와 문단에 중복
- **템플릿 티**: 제품 맥락과 무관한 일반 문구·아이콘·섹션 구성이 그대로 남은 화면
- **가짜 구체성**: 출처 없는 수치·통계·후기, 실제 데이터와 어긋나는 예시 값

**분류**: 기본은 **Friction**(되긴 되는데 신뢰가 안 감). 내용이 사실과 다르거나 사용자를 잘못된 행동으로
이끌면 **Bug**로 올린다. 발견 설명에는 **본 문구를 그대로 인용**하고 위치(화면·라우트·명령어)를 적는다 —
인용 없는 "AI스럽다"는 기록하지 않는다.

인터페이스별로 더 본다:

**Web UI**: 클릭/단계 수, 반응 속도, 빈 상태 UI, 에러 상태 UI, 단축키, 접근성. **시각적 평가는
스크린샷을 근거로 한다** — 화면을 5초 보고 (1) 시선이 가장 먼저 가는 곳이 페르소나 목표와 일치하는가,
(2) 시각적 계층상 중요 정보가 눈에 띄는가, (3) 가독성·정보 밀도가 페르소나 기술 수준에 맞는가를 판정

**CLI**: 에러 메시지→다음 행동 안내 품질, 출력 가독성, `--output json/table` 전환, 파이프 친화성, help 품질, 명령어 직관성

**MCP**: AI 에이전트가 응답만으로 다음 행동 결정 가능성, 에러 응답 구조화, 빈 상태 응답 유용성, 토큰 효율성

**API**: 응답 구조 일관성, 에러 코드/메시지 품질, 페이지네이션, 버전 관리

**Plugin**: hook 방해도, 메시지 명확성, 등록 후 투명한 동작

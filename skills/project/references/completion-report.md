# build 완료 보고 항목

`build.md`의 "완료 보고" 절에서 읽는다. `outcome` 한 줄은 그 절이 정하고, 이 문서는 함께 실을 항목만
정한다. 각 항목은 값이 없으면 "없음"이나 "해당 없음"을 적는다 — 빈 항목과 빠뜨린 항목을 구분한다.

- 처리 이슈: #N — <title>
- **선정 근거**: 이슈 우선순위를 읽었는지, 없어서 기능 우선으로 갔는지(2단계)
- 에픽 정합성: 종결한 에픽, 준비된 하위 이슈, 미완료 에픽의 막힌 대상·해제 조건
- 제외한 비에픽 이슈와 사유(다른 보드 status/게이트/결정대기 등)
- 다른 worktree·remote branch·open PR이 소유한 active claim의 이슈 번호와 branch/PR 근거
- **`build-blocked` 처리한 이슈 번호와 사유** — 어느 게이트에서 두 번 실패했는지
- Coverage 결과: implemented / verified / split / blocked
- **Hollow 점검 결과**(8단계): 이 이슈가 관리·생산 기능이면 소비처를 어디서 찾았는지(코드/백로그
  위치·이슈 번호), 또는 소비처가 없어 만든 `question` 추적 이슈 번호
- **자격 증명 fail-fast Req가 있으면**: 이슈 번호, 값 없을 때의 오류(실제 출력), 막히는 기능 경로
- **리서치 기본값 Req가 있으면**: `question` 이슈 번호, 근거로 삼은 표준·관행·법률의 **출처**, 채택한
  기본값과 코드 위치. 근거가 안 나와 제외한 이슈가 있으면 그것도 사유와 함께
- 검증 결과 / PR 링크 / merge 결과. **리뷰가 코드를 고쳐 재검증했으면 그 사실과 재검증 출력**
- **배포 결과**: `## Deploy` 절이 있었으면 실행한 명령과 헬스체크 결과, 없었으면 **"이 루프는 배포하지
  않음 — CI가 배포했을 수 있으나 미검증"**
- **리뷰 결과**: `--skip-review`이면 `skipped (--skip-review)`. 아니면 `review_status` 줄 그대로,
  `queue_by_pass`, 결함 수·심각도, 고친 항목, **보류(`hard-gates.md` 결정 필요)·범위 밖·미검증
  관찰(`unverified`) 발견 전문**. 이 셋은 게이트 카운트에서 빠진 항목이라 적지 않으면 사람이 그
  존재를 모른다. 보류·범위 밖은 후속 이슈로도 등록되므로 그 이슈 번호를 함께 적는다
- 스스로 결정한 애매한 선택과 근거(있으면)

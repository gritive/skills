# project build — 커밋·리뷰·PR (subagent용)

`build.md`의 9.5단계에서 dispatch된 **subagent가 읽는 문서**다. 구현이 끝난 워킹 트리를 받아
`/ship`으로 커밋 → 리뷰 → PR까지 하고, 9.5단계의 반환 계약대로 결과를 돌려준다.

**여기 없는 것은 오케스트레이터의 몫이다** — 이슈 선정(0~3단계), 구현·검증·Audit(4~8단계, 다른
subagent가 이미 했다), 자격 증명/`question` 이슈 생성(9단계, 이미 끝났다), land-and-deploy·머지
(10단계), 다음 이슈(11단계), 자동 진행 중단 조건, 완료 보고. 전부 `build.md`에 있다.

**브랜치를 새로 따거나 바꾸지 않는다.** 오케스트레이터가 넘긴 작업 브랜치에서 작업한다.

**구현을 다시 하지 않는다.** 워킹 트리의 변경은 이미 Coverage Audit 게이트를 통과했다. 네가 코드를
고치는 것은 아래 "리뷰 auto-fix" 범위 안에서만이다.

## 1. `/ship`을 호출한다 — 절차를 흉내 내지 않는다

`Skill` 툴로 **`ship`을 호출하고 그 지침을 그대로 수행한다.** `ship`이 없으면 아무것도 자체
구현하지 말고 `stopped` + "ship 스킬 없음"으로 반환한다.

**`ship`의 단계를 요약해서 대신 실행하지 않는다.** `gh pr create`를 직접 치는 것으로 대체하지
않는다. 그렇게 하면 이 위임의 이유였던 pre-landing review(Step 9)와 adversarial review(Step 11)가
통째로 사라진다 — 그게 이 단계가 생긴 이유다. `ship`은 재실행이 idempotent하므로, 중간에 멈췄다가
다시 불려도 이미 한 *행동*은 건너뛰고 *검증*은 다시 돈다.

`ship`이 자기 섹션 파일(`sections/*.md`)을 읽으라고 하면 읽는다. 기억으로 대신하지 않는다.

## 2. `ship`이 묻는 것 — 너는 사용자에게 물을 수 없다

**너는 subagent이므로 `AskUserQuestion`이 사용자에게 도달하지 않는다.** `ship`이 사용자 판단을
요구하는 지점에서 네가 임의로 답하면, 그 답은 사람이 승인한 것이 아니라 **에이전트가 자기 작업을
자기가 승인한 것**이 된다. 아래 표대로 처리한다.

| `ship`이 멈추거나 묻는 지점 | 처리 |
| --- | --- |
| pre-landing review(Step 9)가 **ASK 항목**을 냈다 | **답하지 않는다.** `ask_pending` + 항목 전문(각 항목의 심각도·범주 포함)으로 반환. PR을 만들지 않는다 |
| Greptile 코멘트(Step 10)가 사람 판단을 요구한다 | **답하지 않는다.** `ask_pending` + 코멘트 전문으로 반환 |
| 테스트 커버리지가 최소 임계 미만이라 override를 요구한다 | **override하지 않는다.** `stopped` + 실제 수치·출력으로 반환 |
| plan 항목이 NOT DONE이거나 plan 검증이 실패했다 | `stopped` + 어느 항목인지로 반환. 이미 Coverage Audit을 통과한 변경이므로 이 신호는 모순이다 |
| in-branch 테스트 실패, merge conflict, base 브랜치 머지 실패 | `stopped` + 실제 출력으로 반환 |
| **MINOR/MAJOR 버전 범프**를 물어본다 | 이슈 본문의 범위를 근거로 네가 정하고, PR 본문에 그 근거를 남기고, 반환에 "버전 범프: <값> — 근거"를 명시한다. 머지 전이라 되돌릴 수 있고, 오케스트레이터가 반환에서 보고 판정한다 |
| **TODOS.md**를 만들거나 재정리할지 물어본다 | **아니오.** 이 이슈의 범위 밖 파일을 만들지 않는다 |

**`ask_pending`으로 반환하는 것은 실패가 아니다.** 판단이 필요한 항목을 사람에게 올리는 것이 이
경로의 정상 동작이다. 반대로 그 항목을 네가 삼켜서 `shipped`로 돌려주면, 오케스트레이터도 10단계도
그런 항목이 있었다는 것을 영영 모른다.

## 3. 리뷰 auto-fix — 이번 이슈의 변경 파일 안에서만

`ship`이 자동 수정 가능한 발견(데드코드, 스테일 주석, N+1, 포맷 등)을 고치는 것은 정상이고, 그
수정은 커밋에 포함한다. 다만:

- **이번 이슈의 변경 파일 범위 안에서만 고친다.** 리뷰가 그 밖의 기존 코드 문제를 지적하면 고치지
  말고 반환에 "범위 밖 발견"으로 적는다 — 그건 무관 diff이고, 백로그로 갈 일이다.
- **auto-fix가 요구사항 동작을 바꾸면 auto-fix가 아니다.** Coverage Audit이 검증한 동작을 건드리는
  수정은 `ask_pending`으로 올린다.
- auto-fix한 항목과 그 커밋을 반환에 나열한다.

## 4. PR 본문 — 오케스트레이터가 넘긴 5요소가 반드시 들어간다

`ship`은 자체 PR 본문 형식을 갖고 있다. 그 형식을 쓰되 아래를 **누락 없이** 포함시킨다.
오케스트레이터가 dispatch 시 전부 넘겨준다:

1. `Closes #N` — split이면 실제 완료한 서브이슈 번호만
2. 변경 요약
3. **Coverage Audit 요약** (8단계 표)
4. **검증 명령과 실제 출력** (7단계 출력 그대로. 주장이 아니라 출력이다)
5. 남은 항목 없음 — 또는 split/blocked 사유
6. (있으면) 링크할 자격 증명 이슈·`question` 이슈 번호와 "런타임은 #N에 걸려 있다" / "이 구현은
   <표준/법률> 근거의 기본값이며 고객 확인은 #N에서 진행한다"

**실제 시크릿 값을 PR 본문에 쓰지 않는다.**

## 5. 반환 계약

| 경우 | 반환 내용 |
| --- | --- |
| `shipped` | PR 번호·URL, **리뷰가 보고한 결함 전체**(심각도·범주 포함. 없으면 "0건"이라고 명시), auto-fix한 항목과 커밋, 범위 밖 발견, 버전 범프 결과와 근거, PR 본문에 위 5요소가 들어갔는지 |
| `ask_pending` | 사람 판단이 필요한 항목 전문 + 각 항목의 심각도·범주 + `ship`이 제시한 선택지. PR 생성 여부 |
| `stopped` | 어느 조건인지 + 근거(실제 출력) |

**"리뷰 결함 0건"은 "리뷰가 실제로 돌았고 결과가 0건"이라는 뜻이다.** 리뷰가 돌지 않았으면 0건이
아니라 "리뷰 미실행"이라고 반환한다. 오케스트레이터의 자동 승인 조건이 이 값에 걸려 있다.

## Rationalization Table

| 핑계 | 실제 |
| --- | --- |
| "변경이 작고 명백하니 ship 없이 `gh pr create`로 끝내자" | 그러면 pre-landing review와 adversarial review가 사라진다. 이 단계가 생긴 이유가 그 두 리뷰다. 커밋·PR은 이 위임의 부수 효과이지 목적이 아니다. |
| "리뷰 ASK 항목이 사소해 보이니 내가 답하고 진행하자" | 너는 사용자에게 물을 수 없으므로, 네가 답한 것은 사람의 승인이 아니라 에이전트의 자기 승인이다. 항목을 삼키면 오케스트레이터도 10단계도 그것이 있었다는 걸 모른다. `ask_pending`으로 올린다. |
| "커버리지가 임계에 살짝 못 미치니 override하고 넘어가자" | override는 사람의 권한이다. 하드 게이트를 subagent가 여는 순간 게이트가 아니다. `stopped`로 반환하면 오케스트레이터가 판정한다. |
| "리뷰가 기존 코드 문제도 지적했으니 같이 고치자" | 이번 이슈의 변경 파일 밖은 무관 diff다. 고치지 말고 "범위 밖 발견"으로 반환한다. |
| "ship이 리뷰를 돌렸으니 결함 목록은 요약만 돌려주면 된다" | 오케스트레이터의 자동 승인 조건이 심각도·범주에 걸려 있다. 요약하면 판정 근거가 사라진다. 전문을 돌려준다. |
| "PR을 이미 만들었으니 ask_pending 대신 shipped로 돌려주고 항목은 메모로 남기자" | 반환 상태가 오케스트레이터의 분기다. `shipped`는 "사람 판단 대기 항목 없음"을 뜻한다. PR 존재 여부는 `ask_pending` 반환 안에 적는다. |
| "TODOS.md가 없다고 하니 만들어 주자" | 이 이슈의 범위 밖 파일이다. 만들지 않는다. |

## 출력 계약

**대상 프로젝트에 리포트·로그 파일을 남기지 않는다.** 결과는 반환 텍스트로만 돌려준다. PR 본문
초안 등 임시 파일이 필요하면 세션 임시 디렉터리에 둔다. `ship`이 만드는 CHANGELOG·VERSION 같은
저장소 산출물은 그 스킬의 본업이므로 여기 해당하지 않는다.
